# Valkey Transit Encryption Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable TLS-in-transit and AUTH on the production Valkey (ElastiCache) replication group, migrating `CACHE_MASTER_URL` from a plain-HTTP ConfigMap value to a `rediss://` Secret value synced by the existing External Secrets Operator setup.

**Architecture:** Terraform generates the AUTH token itself (`random_password`, since ElastiCache has no AWS-managed-secret equivalent to RDS's `manage_master_user_password`) and mirrors that exact value into a new AWS Secrets Manager secret, so it reaches the cluster through the same `ExternalSecret` mechanism the previous wave already established for `DATABASE_URL`. No application code changes — the `iovalkey` client already auto-detects `rediss://` and extracts credentials from the URL.

**Tech Stack:** Terraform (`hashicorp/aws` `~> 6.0`, `hashicorp/random` `~> 3.6` — both already used in this module), the existing External Secrets Operator install from the prior `external-secrets-operator` plan.

## Global Constraints

- `aws_elasticache_replication_group.core_server` gets `transit_encryption_enabled = true`, `auth_token = random_password.valkey_auth_token.result`, `auth_token_update_strategy = "SET"` (first deploy, no live traffic yet — `"SET"` is correct; `"ROTATE"` is only for adding auth to an already-serving cluster without downtime).
- The AUTH token is generated by Terraform (`random_password`, `length = 32`, `special = true`, `override_special = "!$^-"` — deliberately narrower than AWS's full allowed set of `!&#$^<>-`, to guarantee the value can never collide with URL syntax: `#` is a URL fragment delimiter, `&`/`<`/`>` carry special meaning in some URL/HTML contexts, and none of the four are needed to satisfy AWS's "at least one non-alphanumeric" requirement).
- The same token value is mirrored into a new `aws_secretsmanager_secret` + `aws_secretsmanager_secret_version` named `ruguin/production/valkey-auth-token` — this is the one secret in this whole initiative where Terraform manages the version directly (the value originates in Terraform via `random_password`, so there's no operator to defer to, unlike `docs_password`/`honeycomb_api_key`/`ghcr_token`).
- The existing `module.external_secrets_irsa`'s `permissions.secrets_read.resources` list gains `aws_secretsmanager_secret.valkey_auth_token.arn`.
- `CACHE_MASTER_URL` moves from `kubernetes_config_map.core_server_config` (plain ConfigMap) to the existing `kubectl_manifest.core_server_secrets` `ExternalSecret`'s `template.data`, as `"rediss://:{{ .valkeyAuthToken }}@${aws_elasticache_replication_group.core_server.primary_endpoint_address}:6379"` — no username before the colon (ElastiCache uses AUTH-token-only auth here, not RBAC usernames); confirmed empirically that `new URL("rediss://:token@host:6379")` parses `username=""` and `password="token"` correctly.
- No changes to `apps/core-server` application code, `packages/cache`, or `packages/env` — `CACHE_MASTER_URL: z.url().optional()` already accepts any valid URL scheme, and `iovalkey`'s `Redis` client already auto-enables `tls: true` for `rediss://`/`valkeys://` URLs and extracts the password from the URL's userinfo.
- No real `terraform apply` runs against AWS in this plan (no credentials, backend still an unfilled bootstrap placeholder) — verification is `terraform fmt -check`, `terraform init -backend=false`, `terraform validate`, `tflint`, matching every other Terraform change in this repo this session.

### Task 1: Generate the AUTH token, enable transit encryption, mirror the token into Secrets Manager

**Files:**
- Modify: `infrastructure/terraform/data.tf`
- Modify: `infrastructure/terraform/external-secrets.tf`

**Interfaces:**

- [ ] **Step 1: Add the `random_password` resource and update the ElastiCache replication group in `data.tf`**

Find this exact block in `infrastructure/terraform/data.tf`:

```hcl
resource "aws_elasticache_replication_group" "core_server" {
  replication_group_id = "${local.cluster_name}-core-server"
  description          = "Valkey cache for core-server"
  engine               = "valkey"
  engine_version       = "8.0"
  node_type            = "cache.t4g.micro"
  num_cache_clusters   = 1
  port                 = 6379

  subnet_group_name  = module.vpc.elasticache_subnet_group_name
  security_group_ids = [aws_security_group.elasticache.id]

  automatic_failover_enabled = false

  # AWS-managed KMS key, no application-side change. Transit encryption and an AUTH token are the
  # missing half — both need `CACHE_MASTER_URL` moved to `rediss://` and the cache client verified
  # against TLS + AUTH first, so they're deferred (see the design doc's Riscos).
  at_rest_encryption_enabled = true

  tags = local.tags
}
```

Replace it with:

```hcl
resource "random_password" "valkey_auth_token" {
  length  = 32
  special = true
  # AWS allows !&#$^<>- as specials in ElastiCache auth tokens, but this is narrower on purpose:
  # '#' is a URL fragment delimiter, '&'/'<'/'>' carry special meaning in some URL/HTML contexts —
  # none of the four are needed to satisfy AWS's "at least one non-alphanumeric" rule, and avoiding
  # them entirely means this value can never collide with URL syntax wherever it's embedded.
  override_special = "!$^-"
}

resource "aws_elasticache_replication_group" "core_server" {
  replication_group_id = "${local.cluster_name}-core-server"
  description          = "Valkey cache for core-server"
  engine               = "valkey"
  engine_version       = "8.0"
  node_type            = "cache.t4g.micro"
  num_cache_clusters   = 1
  port                 = 6379

  subnet_group_name  = module.vpc.elasticache_subnet_group_name
  security_group_ids = [aws_security_group.elasticache.id]

  automatic_failover_enabled = false

  # AWS-managed KMS key, no application-side change.
  at_rest_encryption_enabled = true

  transit_encryption_enabled = true
  auth_token                 = random_password.valkey_auth_token.result
  # SET, not ROTATE: this is a first deploy with no live traffic yet on a passwordless replication
  # group. ROTATE exists to add AUTH to an already-serving cluster without dropping connections —
  # not this case. If this token is ever rotated after a real deploy, switch to ROTATE first.
  auth_token_update_strategy = "SET"

  tags = local.tags
}
```
